# 性能、易用性与稳定性优化验证

## 改动范围

- 播放导航：只维护焦点 ID 和合并后的邻域区间，取消每次对全库分配 Dictionary 和 bool 数组；扫描找到全部焦点后即停止。保持库顺序、首个重复 ID、缺失焦点追加及结果去重语义，并避免极大 radius 的整数溢出。
- 搜索：连续 TextChanged 合并为一个低优先级 UI 回调，读取最新文字；控制器释放后不再执行排队搜索。搜索框内按 Esc 清空文字并保留标签筛选；增加搜索框的无障碍名称、操作说明和提示。
- 设置：替换主文件失败时保留已验证的临时快照；启动恢复时即使文件仍被占用，也保留恢复文件供下次重试。损坏或过期临时文件仍会清理。保存任务提前捕获取消令牌，并在锁内统一清理，避免高频修改造成的已释放令牌源访问。

## 性能测量

本机 .NET 10 Release，同一进程内对比修改前 HEAD 的实现与新实现。预先创建 100,000 个 ID，焦点位于中间，默认半径 64；预热各 10 次，测量各 100 次，输入构造不计入。耗时受运行环境影响，这不是整体播放性能指标。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 每次托管分配 | 3,153,594 B | 11,984 B |
| 平均导航构造时间 | 2.674 ms | 0.566 ms |
| 返回条目数 | 129 | 129 |

额外分配随焦点和实际返回邻域增长；焦点缺失时仍需扫描全库。增加的 10 万条回归测试要求单焦点分配低于 64 KiB，避免将来重新引入全库索引。
